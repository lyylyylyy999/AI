## 概念订正

1. `Path(__file__).resolve().parent` 基于源文件位置；当前工作目录基于进程从哪里启动，两者可以不同。
2. `major_stats` 的 key 是专业名称，value 是包含 `total` 和 `count` 的嵌套字典，不只是单个分数。
3. `argv=None` 让 argparse 读取真实进程参数；`main([])` 在测试中模拟没有命令行参数。
4. stdout 与 stderr 是两条输出流；退出码是供操作系统或脚本判断成功与失败的整数状态。
5. mypy 不只检查返回值，也检查参数、赋值、容器元素和可能的 `None`。

## 代码审查结论

当前实现满足功能要求。后续建议把：

```python
def pass_score(scores: list[int], passed_score: int)
```

调整为：

```python
def pass_score(
    scores: list[int], passing_score: int = 60
) -> tuple[int, float]:
```

这能保留旧调用方式，并统一使用 `passing_score` 这一名称。CLI 帮助文字也应面向用户描述功能，而不是描述内部实现。
